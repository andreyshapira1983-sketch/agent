# Орган фальсифицируемого подъёма — проектная записка (MIR-096)

> Статус: ПРОЕКТ, не реализация. Заказ оператора 2026-08-27: «бери
> наблюдательный класс, потом орган MIR-096». Норма, которой подчинён дизайн:
> **обучение фальсифицируют, не строят** — гипотеза без различающего
> эксперимента не становится уроком.

## Зачем (одним абзацем)

Провал → наблюдение работает живьём (27 строк в `data/causal_observations.jsonl`,
вход почищен: сенсор MIR-015 больше не кормит канал словарными промахами).
Подъём наблюдения к уроку вызывается только рукой (`:causal`). Из-за этого
урок из ошибки не доходит ни до одного канала, который читают позже
(MIR-096), а единственный обходной путь — ярлык `lesson` без проверки — это
одновременно дверь атаки (MIR-121) и 87 % непроверенного самоговорения
(MIR-115). Орган делает подъём работой, которую агент выбирает и оплачивает
сам, — и тогда вход по ярлыку можно будет сузить, не закрывая обучение.

## Конституция органа (ограничения, каждое — из ратифицированной нормы)

1. **Гипотезы фальсифицируемы или не принимаются.** Каждое объяснение несёт
   `predicts`: проверяемое следствие («если причина X, то в журнале/переигровке
   Y»). Объяснение без предсказания отбрасывается на разборе ответа модели —
   это ворота качества продукта, как AST-сита Stage A.
2. **Минимум два конкурирующих объяснения** — требование самой лестницы
   (`blocking_reason`). Одно объяснение = подтверждение задним числом, запрещено.
3. **Автор не судит себя (MIR-119).** Выбор победителя делает НЕ модель-автор
   гипотез, а исход различения: детерминированная проверка предсказания по
   журналам, где возможна, иначе — эксперимент (AB-водитель). Слово модели
   о собственной гипотезе никогда не является уликой.
4. **Урок входит в память через ОБЫЧНЫЕ ворота, не через ярлык.** Продукт
   состояния LESSON пишется с происхождением (наблюдение + улики различения)
   и проверенными кусками; ярлык `lesson` ему не нужен. Это и есть «второй
   путь», которого ждут MIR-115/121.
5. **Сигнал и действие — одним пакетом (урок MIR-179).** Сигнал бэклога
   «наблюдения без объяснений» не появляется раньше, чем картограф умеет его
   заземлить и исполнитель умеет исполнить.
6. **Один подъём за цикл, деньги под потолком MIR-149.** Сигнатура действия
   попадает под межзапусковый потолок 400 единиц автоматически; никакого
   собственного бюджета орган не заводит.
7. **Незнание — не приговор.** Непроверяемое предсказание оставляет заявку в
   EXPLAINED с честной причиной, а не проваливает её; REFUTED — полноценный
   исход, не ошибка (опровергнутая гипотеза — тоже знание).

## Поток (три действия кампании)

```
[сигнал] unexplained_causal_observations: N штук, старейшее D дней
   ↓ картограф (grounds = цитата из журнала наблюдений)
[действие 1] explain_causal_observation   — LLM: 2–3 конкурирующих объяснения
                                            с предсказаниями → claim EXPLAINED
[действие 2] discriminate_causal_claim    — проверка предсказаний:
                                            (а) детерминированная по журналам,
                                            (б) AB-эксперимент, где применим;
                                            исход: chosen+invariant → ATTRIBUTED,
                                            либо REFUTED, либе «непроверяемо» (стоит честно)
[действие 3] mint_causal_lesson           — ATTRIBUTED+generalized → запись урока
                                            с происхождением через обычные ворота
```

Каждое действие двигает ОДНУ заявку на ОДНУ ступень; `blocking_reason` сам
говорит, какое действие нужно какой заявке — картограф выбирает по нему.

## Ломки, которые обязаны кусать (свидетели до кода)

- объяснение без `predicts` не принимается (ворота продукта);
- одно объяснение не создаёт EXPLAINED (лестница уже требует двух — пин);
- слово автора не различает: заявка без исхода проверки не становится ATTRIBUTED;
- REFUTED не теряется и не переиспытывается той же гипотезой;
- урок, отчеканенный действием 3, несёт происхождение и проходит обычные
  ворота допуска (не ярлык);
- сигнал не появляется без исполнителя (анти-MIR-179 пин).

## Порядок реализации (слайсы, каждый со своей ломкой)

1. Сигнал + картограф + действие 1 (синтез гипотез, разбор, ворота качества).
2. Действие 2, детерминированная ветвь (проверка предсказаний по журналам).
3. Действие 2, экспериментальная ветвь (обобщение AB-водителя за пределы
   уроков-правок) — отдельный заход, у водителя лесс-специфичная сигнатура.
4. Действие 3 + сужение входа по ярлыку (MIR-115/121) — ТОЛЬКО после того,
   как первый живой урок пройдёт весь путь: закрывать старую дверь до
   открытия новой запрещено уроком MIR-096.

## Подтверждение жизнью (критерий закрытия MIR-096, без изменений)

Урок из провалившегося прогона достигает канала, который читает следующий
прогон; чтение причинно (происхождение прослеживаемо); карантин, потолок FIFO
и success-only переоценены против нового пути; и невиданная форма того же
класса ошибки остановлена изменившимся поведением — живой прогон, не тест.
