# Карта проекта

Чертёж программы: что во что переходит при запуске. Рисуется по мере аудита —
только маршруты, пройденные и проверенные по коду. Ничего не выведено «по
смыслу», ничего не сгенерировано автоматически.

Этот файл — операторский, поэтому он по-русски; долговечная проектная
документация в `docs/` ведётся по-английски. Указатель по всем документам,
заведённым агентом: [OPERATOR_NOTES.ru.md](OPERATOR_NOTES.ru.md).

## Условные обозначения

| знак | значение |
|---|---|
| `→` | вызов: управление уходит туда и (обычно) возвращается |
| `├─ / └─` | развилка: выполняется одна из ветвей |
| ✔ | маршрут пройден аудитом: прочитан построчно и проверен ломкой |
| ○ | связь проверена по коду, но файл ещё не пройден построчно |

## Запуск

```
python main.py
   │
   ▼
main.py                                    ✔  5 строк, только вызов
   │
   ▼
cli/app.py : run_cli()                     ✔  весь порядок запуска здесь
   │
   ├─ 1. app/io.py : _force_utf8_io()      ✔  консоль в UTF-8, до вывода --help
   ├─ 2. cli/args.py : build_parser()      ✔  разбор ключей команды
   ├─ 3. два быстрых пути без агента:      ○  :self-build-propose, :schedule-disable
   ├─ 4. load_dotenv(workspace/.env)       ○  настройки из папки, не из места запуска
   ├─ 5. cli/resume.py : resolve_resume()  ○  только при --resume
   ├─ 6. app/bootstrap.py : build_agent()  ○  сборка агента
   │
   └─ 7. развилка по режиму:
         ├─ есть --ask  →  cli/one_shot.py : run_one_shot()   ○  один вопрос, ответ, выход
         └─ нет --ask   →  cli/repl.py : run_repl()           ✔  диалог с приглашением >
```

Проверено: `cli/app.py` действительно импортирует и вызывает обе ветви (строки
173 и 226), и других вызовов `run_repl` / `run_one_shot` в программе нет —
только в тестах.

## Диалог: [cli/repl.py](../cli/repl.py) ✔

Всё, что между клавиатурой оператора и агентом.

```
run_repl()  — цикл: одна итерация = одно сообщение
   │
   ├─ читает через _StdinLineReader ─ единственный владелец ввода
   │     ├─ _pump()          фоновый поток-демон, складывает строки в очередь
   │     ├─ read_line()      достать строку (можно с ограничением ожидания)
   │     ├─ prompt_line()    строка с приглашением "... "
   │     └─ read_message()   одно сообщение; склеивает вставку через _coalesce_burst()
   │
   ├─ режимы ввода:
   │     ├─ <<< … >>>          →  _collect_pasted_block()        ✔ вынесен
   │     ├─ строка с \ в конце →  _collect_continuation()        ✔ вынесен
   │     ├─ :operator-task…:end →  _collect_operator_task_block() ✔ вынесен
   │     └─ :task-begin…:task-end → _collect_instruction_buffer() ✔ был вынесен ранее
   │
   ├─ команды на двоеточие  →  cli/command_dispatch.py           ○
   ├─ обычная речь          →  cli/intent_bridge.py              ○
   └─ вопрос агенту         →  _ask_the_agent()
                                  └─ app/budget_guard.py         ○  запуск под присмотром бюджета
                                        └─ ответ печатается через core/loop.py
```

Блок `:operator-task` уходит в `app/operator_task.py` ○ и агенту не передаётся.

**Чем проверено:** файл прочитан построчно 2026-08-06; 31 поломка внесена
инструментом мутаций, 9 поломок — вручную по маршруту `<<<` (отдельно сама
разборка, отдельно её связь с циклом). Подробности и цифры —
[docs/CODE_NOTES.md](CODE_NOTES.md).

## Что ещё не нанесено

Честный список белых пятен, чтобы карта не выглядела полнее, чем она есть:

- `cli/one_shot.py` — вторая ветвь развилки, не пройдена;
- `app/bootstrap.py : build_agent` — из чего собирается агент;
- всё, что дальше `_ask_the_agent`: `core/loop.py` и его модули — самая крупная
  часть программы, здесь не нанесена вовсе;
- `cli/command_dispatch.py` — около 230 команд на двоеточие;
- фоновая служба (`app/daemon.py`) и планировщик задач.

**Правило пополнения:** маршрут наносится только после того, как пройден по
коду; связь, которую не подтвердил чтением или прогоном, не рисуется совсем.
Лучше белое пятно, чем красивая стрелка, которой нет в коде.
